.claude 설정 CoreBridge 재작성

2026-07-23 22:29

Picket에서 복사된 .claude/ 디렉토리(CLAUDE.md, rules, skills)를 실제 CoreBridge 프로젝트에 맞게 전면 재작성

작업 요청 요약

.claude/ 디렉토리가 Picket(공연 예매 플랫폼) 프로젝트에서 그대로 복사되어, 현재 프로젝트인 Halo-CoreBridge-BE(채용 파이프라인 관리 ATS)와 내용이 불일치. 프로젝트를 파악한 뒤 예시와 내용을 CoreBridge에 맞게 수정 요청.

사전 계획

  • Explore 에이전트로 프로젝트 전체 탐사 (스택, 패키지 구조, 컨벤션, 인프라, 브랜치)
  • 사용자 확인: DTO 규칙은 레이어 분리 유지(목표 컨벤션), 브랜치는 실제 흐름(dev 기준) 반영, openapi.yaml 규칙 유지
  • CLAUDE.md 전면 재작성, rules 9개 파일 수정, skills 3개 수정, settings.local.json 잔재 제거
  • 검증: Picket 잔재 grep 0건, gradle 명령 실제 실행 확인

탐사 결과 핵심 (Picket 설정과의 차이)

  • CoreBridge = ATS(채용 파이프라인 관리). 멀티모듈: corebridge-core(com.halo.core_bridge) + corebridge-batch
  • Spring Boot 3.5.6, MariaDB, Redis, QueryDSL, Spring Batch, SSE 알림. WebSocket/PortOne/S3 없음
  • 인증: 쿠키 기반 JWT (LoginFilter → JwtAuthFilter → AlreadyLoginFilter), 권한 4종 UserRoleType
  • BaseResponse 필드는 success/code/message/results, 예외는 BaseException.from() 팩토리
  • .env 없음 → application-{dev,prod,token}.yml + 환경변수 방식
  • staging 브랜치 없음 → 작업 브랜치 → dev push 시 GitHub Actions → EC2 자동 배포
  • 기존 DTO는 {Domain}Dto nested static class 패턴 (규칙과 불일치 → 신규 코드부터 레이어 분리 적용으로 명시)
